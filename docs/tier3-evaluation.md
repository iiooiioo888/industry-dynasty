# 第三階加工：評估與暫時不做的理由

## 為什麼想做

`docs/stage-curve.md` 量出兩個結構問題：

1. **中段（11–19 關）靠加工值拉難度，每關只加 4,600**，玩起來像同一關重複九次。
2. **一階天花板 65,000、二階 177,000，中間是空的** —— 技術樹只有兩階，
   難度只能沿著這兩階的產值硬拉。

最直接的解法是加**第三階**：讓合金板（二階成品）變成中間件，
再加工成更高價的產品。

## 實作了什麼

- 新物品 `precision-module`（精密模組，可販售）
- 新配方 `assemble-precision`：合金板 ×2 ＋ 基礎零件 ×2 → 精密模組 ×1
- 一階 65,000 → 二階 177,000 → 三階約 366,000（實測）

## 為什麼撤掉

實作之後跑平衡量測，結果是**第 11–21 關全部變成虧損（−12,000 左右）**，
只有第 22 關（資金最多）變成大賺（+177,000）。

### 更正：我原本的兩個推測，一個是錯的

第一版寫下兩個原因，後來做了隔離實驗：

| 假設 | 實驗 | 結果 |
| --- | --- | --- |
| 新增可販售品項會稀釋 NPC 賣單 | 只加物品、不加配方 | **錯** —— 淨利完全不變（94,937） |
| 排程為了帳面毛利搶料 | 配方存在時淨利 −12,950 | **成立** |

`generateNpcBuyOffers` 是逐品項產生報價的（`SELLABLE_ITEMS.map(...)`），
所以多一個可賣品項**不會**排擠其他品項。我當初把兩件事混在一起講，是錯的。

真正的機制是：`bestReadyRecipe` 依「每週期毛利」排序，三階配方毛利最高，
於是組裝廠全部跑去搶合金板，把原本賣合金板的產線餓死 —— 產線閒置、
產值沒增加，但土地稅與維護照付。

### 第二次更正：真正的死因還沒找到

第三輪（第 11 回合）做了乾淨的隔離，結果推翻上面的推論：

| 實驗 | stage-11 淨利 |
| --- | --- |
| 未改動的樹（clean） | **+94,937** |
| 加入物品＋配方，配方有 `researchId` 且 `isRecipeUnlocked(...)` 回傳 `false` | **−12,950** |
| 同上，但把新物品改成 `sellable: false` | **−12,950** |

也就是說：

- **解鎖條件確實生效**（`isRecipeUnlocked(RECIPES['assemble-precision'], [])` → `false`）
- **新物品不可販售**，所以不會影響 NPC 報價
- 但淨利仍然從 +94,937 掉到 −12,950

**排程搶料、販售稀釋這兩個解釋都不成立。** 這是一個還沒定位的交互作用：
只要 `RECIPES` / `ITEMS` 多了這一組條目，模擬結果就會改變，即使它理論上
完全不會被選到。

線索：在第 6 天觀察，組裝廠完全沒有排到 `make-alloy-plate`，
庫存裡只有原料（`raw-ore` / `resin`），加工產值為 0 —— 但同樣的觀察
還沒在 clean 樹上做過對照，所以這條線索也還沒證實。

（第一輪的「只加物品」實驗得到 94,937 不變，但那次物品其實沒真的加進
`ITEMS` 表 —— TypeScript 當時就報錯，我卻把那個數字當成結論。這是我的錯。）

## 順手修掉的真 bug

`RecipeDef.researchId` 先前**完全沒被檢查**：

```ts
// 修正前：只要原料夠、毛利高就會被排進去
.filter((recipe) => (recipe.buildings as readonly string[]).includes(siteFactoryTypeId))
```

目前所有帶 `researchId` 的配方產出都 `sellable: false`，所以靠「不可販售」
意外擋住了 —— 問題沒顯現。但一旦有「可販售但要解鎖」的配方，
自動排程就會無視研究進度直接開跑。

現在改成明確的 `isRecipeUnlocked(recipe, unlocked)`，並有測試覆蓋。

## 若要做三階，需要先解決的三件事

1. **先找出這個交互作用** —— 加了理論上不會被選到的配方，為什麼模擬結果會變？
   在搞清楚之前，任何新配方都可能悄悄改變平衡。
   建議做法：在 `planProductionSlots` 加一個「本次排了哪些配方」的除錯輸出，
   對 clean 樹與加入配方後各跑一次比對。
2. **關卡目標要同步重算** —— 三階產值約 366,000，現有 22 關的目標只到 140,000。
3. **技術樹需要第三階的門檻設計** —— 目前 `techStage` 只有 0/1/2。

在這三件事解決之前，加三階只會讓「可通關」的保證失效。
