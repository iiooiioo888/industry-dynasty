# 端到端可玩性驗證

## 為什麼要做這個

先前的測試分成兩類：

1. **單元測試** —— 測一個模組（配方、估價、路徑…）
2. **報表 harness** —— 用 `reports/full-loop.ts` 跑模擬並量平衡

兩者都不測「**玩家實際下的一連串動作能不能把一局玩完**」。
元件各自能動，不代表串起來玩得通 —— 合約競標就是例子：
它存在十幾輪、有完整測試，卻**沒有任何 UI 入口**（第 16 回合才補上）。

所以加了 `playthrough/first-stage.test.ts`：**只用 `applyWorldAction`**
（和 UI 完全相同的路徑），把第一關從開局打到結束。

## 測到的三件事

### 1. 正確打法真的能通關

腳本玩家做的事和真人一樣：

1. 標下三塊地（一鐵脈、一樹脂沼、一任意）
2. 各蓋一座工坊
3. 用 `ADVANCE_BUILD_TICK` 等完工
4. 兩塊礦脈開採、第三塊壓製基礎零件
5. 每天推進 48 刻（`ADVANCE_SIM_TIME`，和 UI 的時鐘相同）
6. 賣掉**多餘**的貨（產線要用的原料留著）

結果：**第一關通關**（`status === 'won'`）。

這證明「買地 → 建廠 → 開產線 → 賣貨 → 日結」這條路徑是通的，
不是每個元件各自能渲染而已。

### 2. 盲目擴張會虧錢（設計上的陷阱）

第二條測試刻意模擬新手最直覺的策略：**買六塊地、全部開採、只賣原料**。

結果：`lost`，淨利 **−53,916**。

這不是 bug，是設計後果：六塊地的土地稅與維護，撐不起只賣原料的薄利。
測試把它固定下來 —— 如果哪天純開採路線變成賺錢，
`docs/stage-curve.md` 的結論就要重算。

### 3. 第一版的腳本玩家「無腦全賣」根本玩不動

第一次跑的時候加工產值一直是 0。原因不是遊戲壞了，而是腳本每天把
**加工要用的鐵與樹脂也賣掉**，產線永遠等不到料。

改成「保留產線正在用的原料、只賣多餘的」之後就通了。
這也說明遊戲的供料壓力是真實存在的 —— 不是擺設。

## 這個測試沒有覆蓋什麼

- **DOM / 渲染**：沒有瀏覽器自動化工具，所以測的是狀態層，不是畫面層。
- **UI 元件的互動**：按鈕有沒有壞、表單有沒有綁錯，這裡測不到。
- **其他 21 關**：目前只驗證第一關。要擴充的話，把 `STAGE_ID` 參數化，
  用各關的建議規模跑一輪即可。

## 第 19 回合：擴到全部 22 關後發現的問題

把 `playStage()` 套用到 22 關，結果**每一關都在第 2 天就通關**。

不是腳本作弊（第一版我把起始資金調到 90 萬，那才是作弊，已改回關卡原值），
而是：

> **關卡目標是照 `reports/full-loop.ts` 的產出校準的，但那個 harness 嚴重低估產能。**

原因在供料策略：harness 每天把原料賣掉、只保留少量緩衝，
所以它的加工廠常常在等料。實測 harness 跑第一關 25 天只做出
**39,000** 的加工產值；同樣的 3 塊地、用玩家動作跑，**2 天就有 338,000**。

差了將近一個量級。也就是說：

- 22 關的「建議規模」與目標值，都是建立在**低估的產能**上
- `docs/stage-curve.md` 的結論（規模 3→4→6、第 11 關跳躍、第 20 關需要二階）
  在真實玩法下未必成立
- 目前難度曲線整體偏鬆，玩家主流打法會太快通關

## 這件事還沒修

重新校準需要：

1. 用 `playStage()` 量出每關「合理打法下的實際產出」
2. 依那個數字重設目標（而不是依 harness）
3. 重跑 `docs/stage-curve.md` 的規模掃描

在完成之前，`reports/full-loop.ts` 的數字只能當「保守下限」看，
不能當「可達成上限」。
