# 平衡量測：空間效率被數量槓桿壓過

> 這份紀錄的是 rebase 之前、對 `2fe65c5` 的量測。現行 `main` 的規劃日是 48 刻，出貨要走完路程才入帳；稅、維護與通關門檻已改到 `balance/targets.ts`。下文的 500 稅、60,000 門檻與策略淨利不要當成現況。

以 `reports/simulate.ts` 的機器人模擬器對 `main`（`2fe65c5`）量測。
所有數字都是實跑產出，非估算。重跑方式見文末。

> **先更正一項先前的誤判**：先前只看 3 場就說「隨機策略表現不輸設計過的策略」。
> 拉到 108 場後結論相反 —— `random` 是三個可玩策略中**最弱**的。
> 3 場的樣本不足以比較策略強弱，本文全部改用 108 場。

---

## 1. 策略強弱（108 場：6 seeds × 3 起始現金 × 6 局）

| 名次 | 策略                      | 平均淨利 | 中位數   | 最小     | 最大    |
| ---- | ------------------------- | -------- | -------- | -------- | ------- |
| 1    | `rapid-assembly` 趕工組裝 | 205,098  | 202,581  | 191,860  | 225,704 |
| 2    | `cluster` 聚落工坊        | 173,252  | 170,769  | 151,720  | 187,394 |
| 3    | `random` 隨機業者         | 126,782  | 123,817  | −40,628  | 337,541 |
| 4    | `speculator` 圈地投機     | −88,187  | −100,000 | −116,686 | −50,000 |

`random` 的標準差遠大於其他策略（min −40,628、max 337,541），這是預期中的：
它每 tick 只有 55% 機率出價、40% 機率建廠，且地點與廠型全隨機。

**但真正的問題不是名次，是絕對值。** 通關條件是 25 天淨利 ≥ 60,000
（`sales/scenario.ts`），而**完全不最佳化的隨機策略平均就有 126,782**，
是門檻的兩倍以上。門檻對任何會蓋工廠的玩法都不構成挑戰。

## 2. 空間效率的實際影響幅度只有約 10%

`getSiteLogisticsView` 的 `factor` 在 16×12 全部 148 塊可建地上的分布：

```
最低 = 1.0096    最高 = 1.1124    相對差距 = 10.2%
```

換算成單座工坊在最後一 tick 的營運收入（horizon 18、建造 3 ticks）：

|                        | 物流係數 | 該 tick 營運收入 |
| ---------------------- | -------- | ---------------- |
| 全圖最差位置           | 1.0096   | 4,038            |
| 係數基準 1.0（無加成） | 1.0000   | 4,000            |
| 全圖最佳位置           | 1.1124   | 4,450            |

對照組：**一枚土地稅是 500/tick**。也就是說，把工廠從全圖最差的位置
搬到最好的位置，一個 tick 多賺 **412**，還不夠付一塊地的稅。

### 兩個槓桿的比較（都以「再增加一座成本 5,000 的工坊」為基準）

單座工坊在整局（horizon 18、建造 3 ticks）的累積營運收入是 **44,320**，
所以增加第 N+1 座工坊的邊際收入就是 44,320 —— 遠大於任何位置改善。

| 手段                          | 邊際效果                             |
| ----------------------------- | ------------------------------------ |
| 多蓋 1 座工坊                 | 成本 5,000 → 整局多 **44,320** 收入  |
| 把 1 座工坊從最差搬到最佳位置 | 每一 tick 多 412，整局約多 **6,000** |

README 寫的核心迴圈是「**空間效率 × 時間規劃 = 利潤**」，
但在目前的收益模型裡，空間效率的權重遠低於「蓋更多工廠」。

### 位置還是有相關性，只是幅度太小

`factor` 與地塊屬性的 Pearson 相關：

```
corr(factor, roadAccess)        = 0.8957
corr(factor, cityProximity)     = 0.8139
corr(factor, populationDensity) = 0.6996
```

`roadAccess` 與 `cityProximity` 是**直接進入公式**的
（`ROAD_LOGISTICS_WEIGHT = 0.08`、`CITY_LOGISTICS_WEIGHT = 0.06`，見 `buildings/adjacency.ts`）。
`populationDensity` **沒有進入公式**；0.6996 是空間共變（高密度區本來就靠近城市與道路），
不是因果。這點在 README 的敘述「靠近道路決定這些需求運不運得出去」上是一致的 ——
密度影響的是需求與地價，不是產出效率。

**但這裡有一個不對稱**：`demand.ts` 的 `quoteAuctionMinPrice` 會依人口密度、
城市距離、道路可及性**推高拍賣底價**，等於玩家要為位置付溢價，
卻只能換到約 10% 的產出差距。付得多、拿得少。

## 3. 時間規劃因子到了 horizon 末端就飽和

`timePlanningFactor = 0.55 + 0.7 × min(1, operatingTicks / max(1, horizon − buildTimeTicks))`

在 horizon 18 下，**每一種建造期的單座工坊在最後一 tick 的因子都是 1.250**（上限）：

| buildTicks | operatingTicks | 最後一 tick 因子 | 全期總收入 |
| ---------- | -------------- | ---------------- | ---------- |
| 0          | 18             | 1.250            | 52,960     |
| 1          | 17             | 1.250            | 50,080     |
| 3          | 15             | 1.250            | 44,320     |
| 5          | 13             | 1.250            | 38,560     |
| 8          | 10             | 1.250            | 29,920     |
| 12         | 6              | 1.250            | 18,400     |

分母 `horizon − buildTimeTicks` 讓建造期越長、越容易達到上限，
於是**「建造越慢懲罰越大」這個直覺被抵銷掉**：建造慢的唯一後果是少賺幾個 tick，
而「時間規劃」這個宣稱的機制在期末完全沒有區辨力。

## 4. 工廠類型的成本效率是遞減的

| 類型                    | 造價   | 基礎產出 | 產出/成本 | 建造 ticks | 基礎物流 |
| ----------------------- | ------ | -------- | --------- | ---------- | -------- |
| `workshop` 小型工坊     | 5,000  | 3,200    | 0.6400    | 3          | 1.00     |
| `assembly-plant` 組裝廠 | 12,000 | 7,200    | 0.6000    | 5          | 1.12     |

組裝廠的**每元成本產出比工坊低 6.25%**（0.6000 / 0.6400 = 0.9375）。
它仍然在對局中勝出，是因為 horizon 只有 18、且它的基礎係數較高，
但這是短 horizon 的產物，不是設計上的取捨。
在更長的 horizon（例如通關條件的 25 天）下，工坊的數量優勢會追上。

## 5. 這些數字為什麼不能直接當成「平衡已驗證」

`reports/simulate.ts` 與實際遊戲是**兩套不同的收益模型**：

|          | 收益來源                                       |
| -------- | ---------------------------------------------- |
| 模擬器   | `FACTORY_BASE_YIELD × 物流係數 × 時間規劃因子` |
| 實際遊戲 | 配方產出 → 庫存 → NPC 收購 → 運費              |

模擬器**不經過** `production-line.ts`、配方、`sales/` 任何一環。因此：

- 它量不到 `production/logistics.ts` 的距離曲線（那條曲線只被 `production-line.ts` 呼叫）。
- `DataReport` 沒有勝率欄位，無法回答「玩家能不能過關」。
- 人口密度驅動的 `quoteLocalDemand`（在地收購量與單價）不在模型內。

**上表所有數字描述的是「拍賣與建廠的競爭結構」，不是實際玩法的平衡。**

## 建議的處理順序

1. **先讓模擬器走真實生產鏈**，否則後面每一項調整都無法驗證。
   這是其他工作的前提。
2. **重新校準位置溢價與空間效率的比例**：目前「為位置付的溢價」對上
   「位置帶來的產出」嚴重失衡（10% 產出 vs 依密度推高的底價）。
   要嘛放大空間效率的權重，要嘛讓拍賣底價對位置不那麼敏感。
3. **調整通關門檻**：隨機玩法平均 126,782，門檻 60,000 形同虛設。
4. **時間規劃因子在期末飽和的問題**：若要讓「時間規劃」真的成為決策，
   需要讓它有跨 horizon 都存在的區辨力（例如改成累積型而非歸一化型）。
5. **圈地投機**：需要先有賣地或土地增值機制才可能成為可玩策略（見 PR #1）。

## 重跑方式

量測腳本在 PR #1 的分支上；`pnpm -r run test` 會一併執行護欄測試。

```bash
git checkout fix/distance-cost-saturation
pnpm install
pnpm -r run test
```

關鍵量測位置：

- `packages/sim/src/reports/balance-measure.test.ts` — 模擬器與通關條件的參數落差
- `packages/sim/src/reports/speculator-strategy.test.ts` — 圈地投機的 null control 界定
- `packages/sim/src/production/distance-cost.test.ts` — 距離曲線飽和

本文件的策略強弱表來自 108 場取樣；若要重現，把 roster 設為
`DEFAULT_ROSTER`、`gameCount: 6`，掃過 seeds `[1, 7, 42, 4242, 20261016, 999999]`
與 `startingCash ∈ {50_000, 100_000, 250_000}`。
